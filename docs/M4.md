# M4 seeded demo release

Double-click `run-m4.cmd`, open http://127.0.0.1:8000/ and sign in with credentials in `api/.demo-access.json`. Stop with Ctrl+C. PostgreSQL must be running.

Select **M4 showcase - synthetic fixtures**. Each school has three learners with six completed sessions each, all six rotations, keyed responses, exposure logs and draft/approved recommendations. The idempotent seed preserves existing classes.

## Walkthrough

1. Sign in as teacher.a, select the showcase class and inspect a learner timeline and recommendation history. Draft a recommendation and approve/edit/reject it. No model key is needed for the labelled rule-based fallback.
2. Open **Evaluation report** for rotation counts, balance and mean gain. These synthetic outcomes are fixtures, not effectiveness evidence.
3. In an eligible session timeline, choose **Open delayed retention**. Teacher sign-out occurs before pupil handoff. Six distinct questions are marked on the server. Newly completed sessions become eligible after seven days. Teacher-issued retention access expires after eight hours.
4. Use the original class to approve content, assign it and play crossword → baseline → lessons → post-test → results.
5. In **Content & approval**, expand **Create a new content version**, change the JSON version, edit scripts/questions, save, review, approve and assign. Existing snapshots remain unchanged. Only the existing ROOT/STEM/MOSS diagrams and 4×5 grid are supported.
6. Pupil controls offer larger text, contrast and Bahasa Melayu navigation. Assessment content remains English, explicitly stated in the interface.
7. Researcher/admin can export CSV including session-level retention answered/correct counts repeated per concept row. Withdrawn learners are excluded. Admin can inspect audit history.

## Offline limits

An online visit caches the public app shell. Staff API responses and answer keys are never service-worker cached. The authorized current phase is held in sessionStorage until token expiry. Baseline/post answers can queue on the same tab and synchronize sequentially on reconnect using stable idempotency keys. Conflicts remain visible. Keep the tab open until synchronization. Phase changes, crossword checking/hints and retention submissions require connection. This is limited offline phase support, not a fully uninterrupted offline game.
